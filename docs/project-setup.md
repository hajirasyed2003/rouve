| Tool | Version used | Notes |

## Quick start

```bash
# 1. Backend  (http://localhost:8000/api/v1/docs)
cd backend
python3 -m venv .venv
source .venv/bin/activate            # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
cp .env.example .env                 # fill in later; the API starts without a database
uvicorn app.main:app --reload --port 8000

# 2. Frontend (http://localhost:3000)   in a second terminal
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

Open `http://localhost:3000` for the shell and `http://localhost:3000/design-system` for the live
component gallery. Check the API with `curl http://localhost:8000/api/v1/health`.

## Environment variables

Real `.env` files are git-ignored. Only the `.env.example` templates are committed.

**Backend** (`backend/.env`)

| Variable | Used today | Purpose |
|---|---|---|
| `APP_ENV`, `LOG_LEVEL`, `API_V1_PREFIX` | Yes | Mode, logging, route prefix. API docs are disabled when `APP_ENV=production` |
| `CORS_ORIGINS` | Yes | Comma-separated explicit origins; `*` is rejected |
| `DATABASE_URL` | Yes (optional) | Supabase Postgres. `postgresql://` is converted to asyncpg. Use `?ssl=require` |
| `DB_POOL_SIZE`, `DB_MAX_OVERFLOW`, `DB_USE_PGBOUNCER` | Yes | Pool tuning; set `DB_USE_PGBOUNCER=true` only for the transaction pooler (port 6543) |
| `SUPABASE_*`, `JWT_ALGORITHM` | **Reserved, unused** | Supabase Auth milestone |
| `CLOUDINARY_*` | **Reserved, unused** | Image upload milestone |
| `RAZORPAY_*` | **Reserved, unused** | Payments milestone |
| `SHIPROCKET_*` | **Reserved, unused** | Shipping milestone |

**Frontend** (`frontend/.env.local`): `NEXT_PUBLIC_API_BASE_URL` and `NEXT_PUBLIC_SITE_URL` are
documented for the first API call; nothing reads them yet. Supabase, Razorpay and Cloudinary entries are
reserved. Only public values belong in `NEXT_PUBLIC_*`; never put a service-role key or secret there.

## Database notes (Supabase)

- Use the **direct** connection (port 5432) for Alembic. Use the pooler for the running API only if needed, with `DB_USE_PGBOUNCER=true`.
- `GET /api/v1/health/ready` runs `SELECT 1` with a 3-second timeout and reports `ok`, `not_configured` or `unreachable`.
- No business tables exist yet. `app/models/base.py` defines the declarative base with a constraint naming convention; add models in `app/models/` and import them in `app/models/__init__.py` so autogenerate sees them.

## Decisions and deviations from the brief

- **Tailwind v4 CSS-first tokens.** Brand tokens live in `@theme` in `globals.css`; the Day 1 `tailwind.brand.ts` (v3 style) is superseded. `src/lib/brand.ts` mirrors the colours and a unit test fails if they drift.
- **Fonts through Fontsource**, not `next/font/google`, so builds work offline and nothing is fetched from Google at runtime. The fonts are the same as the brand guide.
- **shadcn/ui was not initialised with its CLI** (its registry could not be reached while building). Components follow shadcn conventions (`cva`, `cn`, `Slot`, `src/components/ui/`). Run `npx shadcn@latest init` when you want its generated components; the existing Button stays compatible.
- **Added `backend/app/db/`** to separate connection management from configuration and models.
- Next.js template defaults `cacheComponents` and `partialPrefetching` were kept in `next.config.ts`.
- Logos in the header and footer are the opaque approved files matched to their ground (ivory header, oxblood footer).

## Known limitations

- **Not checked in a real browser.** No browser was available in the build environment, so there are no screenshots and the responsive breakpoints (nav switching at 768px, grid columns) were not seen visually. Navigation behaviour is covered by tests, but jsdom does not apply CSS breakpoints. Please open the app at desktop and phone widths.
- **Supabase not tested against a real project.** The database layer was exercised with a refused connection and in-memory SQLite. The `?ssl=require` and PgBouncer settings follow Supabase guidance but are unverified here.
- Search, account and bag are inert placeholders. Links to unbuilt pages (shop, custom creations, craftsmanship, policies) show the 404 page.
- The home page is a shell, not the campaign homepage. The product photograph is a labelled placeholder; no real product photography exists yet.
- The logo files are opaque rasters. No favicon has been created.
- The footer shows no copyright year (a dynamic year conflicts with Cache Components prerendering; add it with `"use cache"` later).
- No authentication, payments, shipping or Cloudinary integration exists. Their settings are reserved only.
